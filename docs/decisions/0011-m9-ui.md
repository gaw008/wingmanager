# 0011 — M9 界面与体验（2026-10-21）

原型见 `docs/prototype/`（today / calendar / lease），风格参照 Airbnb 房东后台，房东已确认。

| # | 事项 | 决定 | 理由 |
|---|---|---|---|
| 1 | 样式来源 | 去掉 Pico.css，改用自己的设计系统：`docs/prototype/base.css` 搬到 `internal/web/static/app.css`，成为**唯一的**设计变量和组件来源；`icons.svg` 同样搬到 static。M9 完成后 `docs/prototype/` 冻结为参考，不再维护。**取代 PLAN §3 中的 Pico.css 一行** | 设计变量只能有一份 |
| 2 | 信息结构 | 主导航 5 项：今天、日历、短租、长租、账本。头像菜单：房产与单元、联系人、任务、设置、退出登录。"逾期列表"并入长租（筛选标签），"收支报表"并入账本（标签页）；旧地址重定向到新位置 | 原来 12 个平铺菜单让房东自己拼概念 |
| 3 | 手机 | 宽度 < 744px：顶部只留品牌和头像，主导航变底部 5 图标标签栏；页面不出现横向滚动；日历在自己的容器里横向滚动并定位到今天 | 原型已验证 |
| 4 | 交互技术 | 服务端渲染 + 已有的 htmx + 一个小的 `app.js`（抽屉、对话框、菜单、Esc 关闭）。**核心流程不依赖 JS**：所有表单都能普通提交；抽屉和对话框是渐进增强，没有 JS 时链接到完整页面 | 保持零构建、低复杂度 |
| 5 | 计算留在服务端 | 页面上出现的派生数字一律由领域包算好：日历色条位置（半天网格）、账目滚动余额、每月房租付款状态、收款预览（先进先出冲抵哪几个月）。模板和 JS 不重复任何业务规则；收款预览用 htmx 请求服务端 | 规则只在一处 |
| 6 | 日历画法 | 每天两个半格，订单从入住日中午画到退房日中午；超出当月的一端切平；重叠订单分泳道；导入订单的渠道用头像外圈颜色表示；冲突加红框并在页面顶部提示 | 同日交接在视觉上首尾相接，和日期规则一致 |
| 7 | 暗色模式 | 不在 M9 范围，留到 v0.2（设计变量已为此预留） | 控制范围 |
| 8 | 验收方式 | Codex 无法使用浏览器，以原型 HTML 为规格；监督者在 1280px 和 375px 下逐页对照原型验收 | — |
