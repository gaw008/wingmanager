# 0005 — M5（长租）细节决策（2026-10-20）

| # | 事项 | 决定 | 理由 |
|---|---|---|---|
| 1 | 租金周期 | **租金周期一律是自然月**（`period = 'YYYY-MM'`）。`due_day` 只决定应收日期；首个不完整月份的应收日期是 `starts_on`。**取代 PLAN §5 "租约不从 due_day 开始时折算"的写法**，改为：租约不从 1 号开始时首月按天折算；租约不在月末结束时末月也按天折算 | 周期和自然月一致，折算规则只有一条，房东一看就懂 |
| 2 | 折算公式 | 月租 × 当月占用天数 / 当月天数，四舍五入到分（整数运算，0.5 分进位）。只在 `lease` 包一个函数里 | PLAN §5 |
| 3 | 何时生成应收 | 应收日期 ≤ 今天才生成（不提前） | 少一个参数；余额只反映已经到期的钱 |
| 4 | 状态流转 | draft → active → ended。draft 全部可改、不占用单元；激活时要求至少一个租客，并在 IMMEDIATE 事务里检查和 confirmed 订单、其他 active 租约是否重叠。active 只能改月租（只影响以后的应收）、结束日（缩短或延长，延长要查重叠）、租客、备注；不能改 `starts_on` 和 `due_day`（要改就结束后另建）。ended 只能改备注 | 改起始日或收租日会让已生成的应收失去意义 |
| 5 | 自动结束 | 每天的任务把 `ends_on < 今天` 的 active 租约标为 ended；房东也可以手动结束（填结束日） | `status` 和 `ends_on` 不会长期矛盾 |
| 6 | 逾期 | 余额 > 0 且按先进先出计算、最早一笔未付清应收的日期 < 今天，即为逾期，显示逾期天数 | PLAN §5 不做付款分配，逾期由计算得出 |
| 7 | 收款类别 | `payment.category` 表示付款方式：cash、check、bank_transfer、zelle、venmo、card、deposit_applied、other | 一个字段，含义固定 |
| 8 | 押金 | 收押金、退押金都手动记录（`deposit_in` / `deposit_out`）；页面显示"约定押金 vs 实际持有"。"用押金抵欠款"是一个操作：同一事务里记一笔 `deposit_out` 和一笔 `payment`（category = deposit_applied），金额相同 | 押金不是收入；抵扣要两边同时记账 |
| 9 | 作废 | 除自动房租应收外都可以作废，作废必须填原因 | PLAN §5 |
| 10 | 滞纳金 | v0.1 不自动生成，房东手动记 `charge`（category = late_fee） | 各地法规不同，不替房东做主 |
| 11 | 租约占用与导出 | 只有 active 租约占用单元：手动订单要避开它（M3 留的接口），它也要作为 block 出现在导出日历里（M4 留的接口），没有结束日的租约导出到今天起两年 | 避免长租期间又被短租平台订走 |
