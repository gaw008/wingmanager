# 0007 — M7（首页、任务、文件）细节决策（2026-10-20）

| # | 事项 | 决定 | 理由 |
|---|---|---|---|
| 1 | 首页"今天" | 依次显示：今天入住、今天退房（以及未来 7 天的入住/退房）；逾期租客（金额、天数）；今天到期或已过期的未完成任务；有问题的日历源（`last_error` 非空，或超过 24 小时没成功同步）；未来的订单冲突；今年至今净收入（现金制，全部房产）。都是读取现有模块的计算结果，首页自己不写业务规则 | 回答 PLAN §1 的三个问题 |
| 2 | 任务 | 房东可以新建 maintenance / other 任务（房产必填，单元可选，标题必填，到期日可选，负责人是自由文本）；可以标记完成、重新打开、取消。**保洁任务**的生成和取消跟着订单走，房东只能标记完成/重新打开、改负责人和备注，不能手动取消或新建 | 保洁任务的状态只有一个权威：订单 |
| 3 | 文件表 | M7 的迁移按 PLAN §4 建 `documents`，另加可空的 `ledger_entry_id`（0006 #7）；**加 CHECK：property_id / unit_id / lease_id / person_id / ledger_entry_id 恰好一个非空** | 一个文件只挂在一个地方，归属不含糊 |
| 4 | 上传顺序 | 先写临时文件 → 事务里插入记录拿到 id → 把临时文件改名为 `<data-dir>/files/<id>` → 提交。改名失败就回滚；提交失败就删除刚改名的文件 | 不留下"有记录没文件"的坏数据；最坏情况只是一个孤儿文件 |
| 5 | 下载 | 一律 `Content-Disposition: attachment`，`Content-Type` 用服务器检测结果（`http.DetectContentType`），不信任上传时的声明；加 `X-Content-Type-Options: nosniff` | 防止上传的 HTML 文件在浏览器里执行 |
| 6 | 大小上限 | 单个文件 20 MB（命名常量） | 收据、租约 PDF 足够 |
| 7 | 删除文件 | 允许删除：事务里删记录，提交后删磁盘文件 | 房东自己的文件；崩溃时最多留一个孤儿文件 |
