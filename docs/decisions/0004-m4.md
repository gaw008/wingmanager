# 0004 — M4（iCal）细节决策（2026-10-20）

PLAN §6.1 没写到的细节，按"最简单且不丢数据"定：

| # | 事项 | 决定 | 理由 |
|---|---|---|---|
| 1 | 删除日历源 | 同一事务里把它导入的订单全部转成手动订单（清空 `feed_id`、`external_uid`），再删 feed | 历史订单要保留；转成手动后归房东所有，不会因为删源而被批量取消 |
| 2 | 事件分类 | Airbnb：`Reserved` → stay，`Airbnb (Not available)` → block；VRBO：`Blocked` → block，其余 → stay；Booking.com 无法区分，全部 → stay；其他渠道：SUMMARY 含 block / not available / unavailable / closed（不分大小写）→ block，否则 stay。规则只在 `ical/classify.go` | 宁可多一个保洁任务，也不要漏掉真实订单 |
| 3 | 单个事件格式错误 | 整次同步失败、不改任何数据、记录 `last_error` | 跳过事件可能漏掉真实订单；明确报错由房东处理 |
| 4 | 带时间的 DTSTART/DTEND | 按 `settings.timezone` 换成日期；没有 DTEND 时按 1 晚处理 | iCal 全天事件的 DTEND 本来就是退房日，和 `check_out` 语义一致 |
| 5 | 自动保洁任务 | 每个 confirmed stay（手动或导入）在退房日有一个 cleaning 任务；`title` 存空字符串，界面按 kind 显示本地化名称。订单取消 → 未完成的任务改为 cancelled；恢复 → 重新打开；改日期 → 未完成任务的 `due_on` 跟着改；已完成的任务不再变动。block 没有保洁任务 | 任务和订单状态在同一事务里联动 |
| 6 | 导出内容 | 所有 confirmed 订单（stay 和 block，手动和导入都含），`check_out >= 今天`；SUMMARY 固定为 "Not available"，**不含客人姓名**；UID 固定为 `booking-<id>@wingmanager` | 导出链接会交给各平台，不能泄露客人信息 |
| 7 | 导入订单可改字段 | 只能改客人和备注；日期、状态、类型归外部日历 | PLAN §4 字段归属 |
